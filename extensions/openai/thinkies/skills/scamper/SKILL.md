# SCAMPER

Run seven fixed lenses over one concrete thing to produce variations of it, then let the user choose which variations to develop. The lenses work on something that exists: a product, a workflow, a feature. Where the request names a goal and no thing yet, settle the thing in Phase 0 first.

## Phase 0: Clarify

Engage in dialogue to build shared understanding of the request. Reflect back a structured summary: the thing, what it is for, and what the user wants from the variations. Go on once the user confirms the summary in their own words, as in "Yes, that's exactly what I mean."

## Phase 1: Ideate

Apply each SCAMPER lens to the subject the user brought:

- **S (Substitute):** Swap a component to transform it.
- **C (Combine):** Merge with something else to create novelty.
- **A (Adapt):** Borrow from another domain.
- **M (Modify):** Magnify or alter an aspect.
- **P (Put to another use):** Repurpose for a different context.
- **E (Eliminate):** Remove or simplify something.
- **R (Reverse):** Invert or rearrange.

The subject is the thing confirmed in Phase 0. Under each lens, give one to three numbered ideas. Each idea names what changes in the thing and what the change buys against what the user said they want. Where a lens yields nothing worth keeping for this thing, say so in one line and move on.

## Phase 2: Converge

Present a synthesized breakdown of ideas from Phase 1: a few named groups, each listing its ideas by number and saying what the group has in common. Ask the user to select one or more directions, then return to Phase 0 to clarify and confirm the new direction together.

The session ends when the user has a direction they want to build, or says they have enough.

## When nobody can reply

Some runs reach no user: a delegated run, a batch job. There, write the Phase 0 summary as your reading of the request and mark it as unconfirmed. Run Phase 1 once, present the groups, and end on the question Phase 2 asks, so whoever holds the conversation can put it to the user.
